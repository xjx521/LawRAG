# ADR-010：语料用现成资源，不自己写爬虫

> 状态：已采纳 · 2026-09-11

## 背景

项目需要 700-900 条劳动法相关法条原文。

最直觉的做法是写爬虫去国家法律法规数据库（`flk.npc.gov.cn`）抓。用户也倾向于"自己抓的才是自己的"。

## 备选

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. 自己写爬虫抓 flk | 数据最新；"自己动手"的感觉 | 见下 |
| **B. 用现成开源语料** | 已抓全、已结构化、已有交叉校验源 | 可能不是最新版本（要专门验证） |

## 决定

**选 B：用现成资源，精力全部投入结构化解析 + 时效性 + 引用校验。**

### 调研过的现成资源（2026-09-11 核实）

| 资源 | 内容 | 格式 | 定位 |
|------|------|------|------|
| **`Duyu/Chinese_Law`**（HuggingFace） | 宪法/法律/法规/司法解释，**层级最完整** | 结构化 Markdown | ★ **主来源** |
| **`lawtext/law-flk-vol1`**（GitHub） | 来自 flk 的 docx 原文，定期更新 | docx | 补最新版本（2012 修正版劳动合同法等） |
| **`RanKKI/LawRefBook` + `Chinese-Dataset/Laws`** | 聚合 flk + 最高法数据 | `.md` + `db.sqlite3` | ★ **交叉校验**（条数/文本比对） |
| `twang2218/law-datasets` | 爬虫产出，22552 条法规 | `laws.json` | 交叉校验备用 |
| `Jinsns/flk`（HF） | 每行"某法 第n章 第n条 内容" | TSV | ⚠️ **丢了款/项层级**，仅供参考，不能用 |
| `flk.npc.gov.cn` 官方 API | `/api/` 列表、`/api/detail` 详情 | JSON + docx | 定点补最新法规 |

### 为什么不自己爬

1. **已经有人抓全了**，而且转好了格式。写爬虫是在重新解决一个已被解决的问题。
2. **flk 的详情页正文是 OFD 格式**——一种国内专用的版式文档格式，Python 侧解析库极不成熟。硬啃这个格式会吃掉一周，且收获的不是"AI 应用开发"能力。
   → 正确做法是用 `ossWordPath` 拿 docx，或者**直接用开源镜像**。
3. **真正的技术含量不在"抓"，在"解析 + 时效性 + 引用校验"**。这三件事没人替你做，且直接对应论文创新点。

### 法律依据（版权合规）

《中华人民共和国著作权法》**第五条**：法律、法规，国家机关的决议、决定、命令和其他具有立法、行政、司法性质的文件，**不适用本法**。

→ 法条原文属**公有领域**，可以自由下载、分发、提交到公开 git 仓库。

**⚠️ 但边界要划清**：只取**条文本身**。"法条释义""案例评析""学术解读"这类衍生内容**有版权**，不碰。

### ⚠️ 必踩的两个坑（已核实，M2 必须处理）

**坑 1：最新法规可能不在镜像里**

> 《最高法劳动争议司法解释（二）》（法释〔2025〕12号，**2025-09-01 施行**）是 2025 年新出的。**2024 年前抓的镜像仓库基本都没有这部法**。

处理：M2 第二天专门检查这部法在不在，不在就从 `lawtext/law-flk-vol1` 或官方 API 定点补。

**坑 2：时效性字段编码有来源冲突**

> flk 的 `sxx` 字段存在**两套互相矛盾**的编码说法：`3=有效` vs `3=尚未生效`。

处理：**用《劳动合同法》（应为"已修改"）反推编码表，实测验证，不许盲抄任何一方。**

这条本身就是论文/面试的好素材——"我发现公开文档里对同一个字段有两种矛盾的说法，我用一部已知状态的法律反推验证了真实编码"。

### 第一版范围：10-11 部法规

| # | 法规 | 条数 | 覆盖什么问题 |
|---|------|------|------------|
| 1 | **劳动合同法**（2012 修正） | 98 | 试用期(19-21条)、解除(36-50条)、经济补偿(46-47条)、违法解除赔偿金(48、87条)、二倍工资(82条) |
| 2 | **劳动合同法实施条例** | ~38 | 试用期细化、经济补偿计算基数 |
| 3 | **劳动法**（2018 修正） | 107 | 工时/加班(41、44条)、工资(50条)、社保总纲 |
| 4 | **社会保险法** | ~98 | 五险、单位不缴的救济 |
| 5 | **劳动争议调解仲裁法** | 54 | 仲裁时效1年(27条)、一裁终局(47条)、举证责任(6条) |
| 6 | **职工带薪年休假条例** | 10 | 年假天数(3条)、应休未休300%(5条) |
| 7 | **企业职工带薪年休假实施办法** | ~17 | 年假折算、未休补偿计算 |
| 8 | **工伤保险条例**（586号令） | ~64 | 工伤认定、停工留薪期、工伤待遇 |
| 9 | **最高法劳动争议解释（一）** 法释〔2020〕26号 | ~55 | 受理范围、仲裁与诉讼衔接 |
| 10 | **最高法劳动争议解释（二）** 法释〔2025〕12号 | ~30 | **最新**：二次固定期限合同认定、竞业限制、社保纠纷 |
| +11 | **工资支付暂行规定**（劳部发〔1994〕489号） | ~20 | **加班费计算基数**——加班费最直接的依据，必加 |

**为什么是这 11 部**：覆盖劳动法高频问题闭环——试用期 → 加班费 → 离职赔偿 → 年假 → 社保 → 工伤。不追求"全量法规库"，追求**一个问题域讲透**。

**地方差异**（加班费基数、最低工资、经济补偿封顶各省不同）：第一版**不做本地化**，metadata 预留 `region` 字段（默认"全国"）。

## 代价

- **版本可能不是最新** → 必须交叉校验 + 定点补（坑 1）
- **依赖第三方仓库的存活** → 下载后存到 `data/raw/` 进 git（公有领域，无版权风险），不依赖仓库长期可用
- **格式不统一**（Markdown / docx / JSON / TSV）→ 只选层级最完整的一个作主来源，其他只用于校验
- **`Jinsns/flk` 丢了款/项层级** → 明确标记不可用于主链路，因为款级粒度是本项目的核心设计（ADR-009）

## 面试怎么答

> "你的语料是爬的吗？"
>
> 不是，用的现成开源语料。我调研过，`Duyu/Chinese_Law` 已经把法规转成结构化 Markdown 了，层级比我自己抓的还全。而官网详情页的正文是 OFD 格式，Python 解析库很不成熟，硬啃要一周，而且啃出来的是"OFD 解析"能力，跟 AI 应用开发没关系。
>
> 我把精力放在没人替我做的地方：结构化解析——一条一 chunk、五级层级、款级粒度；时效性标注；引用校验。这些才是这个项目真正的技术含量。
>
> 不过用现成语料有个必须处理的问题：**版本可能不是最新的**。2025 年 9 月出了新的《劳动争议司法解释（二）》，2024 年之前抓的镜像基本都没有。所以我专门加了一步校验。还有一个更有意思的事——flk 有个时效性字段，我在两个来源看到对同一个编码值有两种矛盾的解释，最后我是用一部已知状态的法律反推验证的编码表。

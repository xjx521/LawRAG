# ADR-008：毕业设计主体 = 项目一（RAG），Agent 作为模块

> 状态：已采纳 · 2026-09-11

## 背景

用户面临毕业设计与论文。**同学大多做基于 Java/SpringBoot 的简单图书管理系统**，用户明确"不打算跟他们一样"。

手上有两个候选项目：项目一（RAG 知识库）、项目二（AI Agent）。

## 备选

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. RAG 作主体，Agent 作模块** | 边界清晰；有量化指标；演示稳定；论文有实验章 | Agent 部分深度受限 |
| B. Agent 作主体 | 技术更前沿、更酷 | **评估困难**——Agent 的行为是轨迹不是答案，"正确率"难定义；演示不稳定（多步推理可能跑歪） |
| C. 两个并列双主体 | 内容最丰富 | 论文结构散；每个都做不深；答辩时讲不清重点 |

## 决定

**选 A：RAG 作毕设主体，Agentic RAG 作为其中的 M6 模块。**

### 三个决定性理由

1. **RAG 有清晰可量化的评估指标。**
   论文的"实验章"需要数据。RAG 有现成的标准指标：`Recall@5` / `MRR` / `Hit@1` / `Citation F1`。可以做"改一个参数跑一遍，指标从 X 提到 Y"的对照实验。
   Agent 没有这种标准——它的输出是**行为轨迹**（调了几次工具、路径对不对），"正确率"本身就难定义，更别说做对照实验。

2. **RAG 演示稳定，Agent 演示看运气。**
   答辩现场只有一次机会。RAG 问答是确定性的（temperature=0 + 固定检索），**同样的输入必然给同样的输出**。Agent 多步推理，7B 本地模型可能第 3 步就跑歪——gowork 阶段已经反复见过这种失败。

3. **用户已有的知识储备正好匹配。**
   gowork Phase 4（Day50-57）是 RAG 全链路，Phase 5（Day58-61）是 Agent。LawRAG 是 Phase 4 的工程化，**用户对 RAG 的掌握更扎实**。

### Agent 的定位

M6 Agentic RAG 不是"为了用 Agent 而用"，它解决一个**具体的 RAG 问题**：

> 用户的提问可能是复合的——"公司没给我交社保，我能要求什么赔偿？"——单次检索答不了，需要 **query 改写 → 多轮检索 → 综合**。

所以 Agent 作为 RAG 的一个**能力增强模块**存在：
- query 改写节点
- 检索工具化（让 Agent 自主决定查不查、查几次）
- 反思节点（检索结果够不够）
- 护栏（max_iterations，防死循环）

**这比"我做了个 Agent"更值钱**——因为它有明确的动机和边界。

### 论文结构（现成大纲）

见 `docs/PROJECT-MEMORY.md` 和计划文件的第 8.8 节，7 个实验方向：
1. 分块策略对比（一条一 chunk vs 固定滑窗）
2. 检索策略对比（BM25 / 向量 / 混合 RRF / 混合+rerank）
3. 条款号精确查询的价值
4. 时效性处理的价值
5. Agentic RAG vs 传统 RAG（多跳问题）
6. 引用准确性（Citation F1 + 校验器拦截率）
7. 性能（P50/P95 延迟、QPS、成本）

## 代价

- **Agent 深度受限**：不能做多 Agent 协作、复杂工具生态等。→ 接受：那些放到项目二，且**不影响毕设的完整性**。
- **论文的创新点偏工程**（领域特化分块、条款级引用校验、时效性过滤），不是算法创新。→ 接受：本科毕设（尤其民办三本）**工程完整度 + 量化实验**比"算法创新"更实际，也更容易答辩通过。
- **需要写好"为什么不做纯 Agent"的论述**，避免答辩老师问"你怎么不做个 Agent"。→ 已准备好答案（见下）。

## 面试/答辩怎么答

> "为什么不做纯 Agent 项目？Agent 不是更前沿吗？"
>
> 我做了 Agent，但把它放在 RAG 里面当一个模块——因为它解决的是一个**具体的 RAG 问题**：用户的提问可能是复合的，"公司没给我交社保我能要求什么赔偿"，单次检索答不了，需要改写查询、多轮检索、再综合。这个场景下 Agent 是有必要的，不是为了用而用。
>
> 至于为什么不把 Agent 当主体：**评估**。RAG 有现成的量化指标，Recall@5、MRR、Citation F1，我能说"改了参数指标从多少提到多少"。Agent 的输出是行为轨迹，正确率本身就不好定义，我没法在毕设里做出可靠的对照实验。而论文需要数据。
>
> 另外答辩要现场演示，RAG 是确定性的，同样输入必然同样输出；Agent 多步推理用 7B 本地模型可能第 3 步就跑歪。我选能让演示稳的那个。

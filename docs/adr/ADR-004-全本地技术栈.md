# ADR-004：技术栈全本地（Chroma + MySQL + Ollama）

> 状态：已采纳 · 2026-09-11

## 背景

需要选定三类基础设施：向量库、关系库、LLM。用户的既有条件：有 NVIDIA 显卡可本地跑模型，已有 Ollama 环境（`D:\Ollama\models`，`bge-m3` 已拉取），gowork 阶段已用 DeepSeek API 做过实验。

## 备选

| 组件 | 选项 | 决定 |
|------|------|------|
| 向量库 | Chroma / Qdrant / Milvus / pgvector | **Chroma** |
| 关系库 | MySQL / PostgreSQL / SQLite | **MySQL** |
| LLM | 本地 Ollama(qwen2.5:7b) / 云端 API | **本地 Ollama，云端作降级备选** |

## 决定

### 1. 向量库 = ChromaDB

**理由**：gowork 阶段（Day52-57）已经用它做过完整实验，用户熟悉 API 和它的坑（L2 距离方向、metadata 过滤、持久化）。

**但明确知道它的局限**（这是 ADR 存在的意义）：

| 指标 | ChromaDB | Qdrant | Milvus |
|------|----------|--------|--------|
| QPS | ~423 | ~1245 | ~1180 |
| SIFT1M 建索引 | 595.2s | — | 198.1s |

**所以它不是"最佳选择"，而是"当前最优选择"**——够用、上手快、能跑通。真正的工程价值在于：

> `VectorStore` 写成**抽象接口**，Chroma 只是其中一个实现类。换 Qdrant 只改实现，不改上层。

这样规格表第 4 条（"10 万文档会怎样"）才有答案：**先撑不住的是 Chroma 的全量加载和 BM25 的全内存**，而我们有抽象层，换实现类即可。

### 2. 关系库 = MySQL

**理由**：gowork 阶段（Day30-32、Day39-40）用过，异步 SQLAlchemy + Alembic 迁移的完整链路已经走通一遍。

它承载的是"**真相源**"角色——`chunks` 表的原文才是权威数据，向量库只是索引（铁律第 5 条）。所以关系库在这个项目里的地位比一般 RAG 项目更重。

### 3. LLM = 本地 Ollama（qwen2.5:7b）

**理由**：

- **零成本**：开发期要跑几百次评估，用云端 API 是烧钱
- **可离线**：答辩现场断网也不翻车（这是真实风险）
- **数据不出本地**：法律场景虽然用的是公开语料，但养成习惯
- **有显卡**：用户有 NVIDIA 显卡

**已知短板**：qwen2.5:7b 是 7B 小模型，gowork 阶段实测已暴露它的问题——Day53 当重排器"帮倒忙"、Day59 `read_note` 读出来但下一轮不转述。这些不是 bug，是模型能力上限。

**应对**：`LLMProvider` 抽象接口 + 环境变量切换（`LLM_PROVIDER=ollama|deepseek`）。开发用本地，演示/对比实验需要强模型时切云端。

### Embedding 保持 `bge-m3`（1024 维）

gowork 阶段实测过的中文 RAG 事实标准。法律专用可试 `ChatLaw-Text2Vec`（北大，93w 判决案例训练），但**先不换**——换 embedding 意味着全量重算向量，是"以后有需要再说"的事。

## 代价（必须知道，面试会被问）

| 代价 | 具体影响 | 缓解 |
|------|---------|------|
| **7B 模型能力有限** | 复杂推理、严格格式遵循会翻车 | Provider 抽象，可切云端；评估时如实记录模型限制 |
| **Chroma 性能天花板** | 10 万级文档会明显变慢 | VectorStore 抽象；论文里写清楚瓶颈在哪 |
| **本地跑模型吃显存** | 同时跑 LLM + embedding 可能 OOM | 错峰调用（embedding 在导入期，LLM 在问答期） |
| **复现成本** | 面试官 clone 下来没法直接跑（要装 Ollama + 拉模型） | README 写清楚步骤；`docker compose` 提供基础设施 |

## 面试怎么答

> "为什么用 Chroma 不用 Qdrant？"
>
> 我不用"Chroma 更好"来回答，因为它不是更好——公开基准里 Qdrant 的 QPS 大概是 Chroma 的三倍，建索引也快得多。
>
> 选它是因为**够用 + 我熟悉**。我的语料是几千条法条，不是千万级向量，Chroma 的性能天花板不是我的瓶颈。
>
> 但我知道它有限，所以 `VectorStore` 是抽象接口，Chroma 只是实现类之一。真到十万文档，我要做的是换实现类，而不是重写检索层。这个抽象不是过度设计——它让我能诚实地说出"我的系统瓶颈在哪、怎么解决"。

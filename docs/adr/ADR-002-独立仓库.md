# ADR-002：独立仓库 `D:\LawRAG`

> 状态：已采纳 · 2026-09-11

## 背景

用户的学习仓库 `D:\Go work` 已有 85KB 的 `CLAUDE.md`，混合存放了从 Python 基础到 Agent 的全部学习记录和实验脚本。

LawRAG 是一个**要投简历、要答辩、要给面试官看**的项目。

## 备选

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. 独立仓库 `D:\LawRAG`** | 简历上一个干净的独立链接；token 成本可控；git history 干净 | 需要复制 venv；两个仓库要分别提交 |
| B. 放在 `D:\Go work` 下的子目录 | 复用现有环境，不折腾 | **面试官打开会看到一堆学习笔记**；85KB CLAUDE.md 每次会话全量加载 |
| C. 独立仓库但共用 venv | 省 936MB | 路径耦合，且两个项目依赖会互相污染 |

## 决定

**选 A：独立仓库 `D:\LawRAG`，复制 venv，独立 CLAUDE.md。**

### 三个理由

1. **面试视角**：简历上放 `github.com/xxx/LawRAG` 而不是 `github.com/xxx/学习笔记/Day43-61`。招聘方点开看到的应该是 README、架构图、测试，而不是学习历程。

2. **Token 成本**（这是用户明确提出的要求）。
   `D:\Go work\CLAUDE.md` 已膨胀到 85KB，每次会话自动加载。LawRAG 的 `CLAUDE.md` 目标 **<8KB**，把详细内容拆到 `docs/` 按需读。这不是洁癖，是实打实省 token。

3. **CLAUDE.md 分层设计**：

   | 文件 | 大小 | 加载时机 | 内容 |
   |------|------|---------|------|
   | `CLAUDE.md` | **<8KB** | 每次自动加载 | 用户背景摘要 / 项目约定 / 里程碑进度 / 决策索引 |
   | `docs/PROJECT-MEMORY.md` | 不限 | 按需读 | 对话关键结论 / gowork 学习历程 / 详细背景 |
   | `docs/adr/` | 不限 | 按需读 | 架构决策（面试前通读一遍） |
   | `docs/面试弹药库.md` | 不限 | 按需读 | 数字/参数/出处 |

   效果：日常会话只加载 8KB，需要背景时再翻。

### venv 复制的实际代价

复制 venv **不是** `robocopy` 完就能用。Windows venv 里有两处内嵌绝对路径：

1. 纯文本：`Scripts/activate`、`activate.bat`、`activate.fish`
2. **`.exe` 启动器**：格式 `[PE 二进制] + [shebang 行] + [内嵌 zip]`，旧路径在 zip 前面的 shebang 里
   - 判定方法：`venv/Scripts/pip.exe --version` 会打印它实际用的 venv 路径
   - 修法：定位 zip 起点，只替换起点之前的字节（长度变化不影响，启动器靠扫 EOL 定位）

踩坑记录见 `docs/PROJECT-MEMORY.md` 第六节。

## 代价

- **多占 936MB**（D 盘剩余 287G，可接受）
- **两个仓库要分别 commit**：gowork 记学习历程，LawRAG 记项目。学习收获写 gowork，项目决策写 LawRAG 的 ADR，不混。
- **venv 路径修复是一次性额外工作**（已解决，做一次以后不用管）

## 面试怎么答

> "你的项目和你的学习记录是分开的吗？"
>
> 是。学习仓库记录我从 Python 基础到 Agent 的完整历程，项目仓库是独立的生产级代码。分开的好处是项目仓库的 git history 是干净的——每一条 commit 都对应一个真实的功能迭代，面试官翻 commit 看到的是"实现混合检索""补充评估指标"，而不是"Day43 练习"。

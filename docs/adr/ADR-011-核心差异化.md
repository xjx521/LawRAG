# ADR-011：核心差异化 = 时效性处理 + 条款级引用校验

> 状态：已采纳 · 2026-09-11

## 背景

市面上 RAG 知识库项目极多（用户自己就列了 6 个开源项目，Dify 93.7K star）。**一个"能建库、能上传、能问答"的系统，今天没有任何区分度**——面试官见过几百个。

所以必须回答：**通用平台做不了、而我做了的是什么？**

## 备选

| 方向 | 是否选 | 理由 |
|------|--------|------|
| 更好的 UI | ❌ | 没有技术含量，且不是 AI 应用开发的考点 |
| 更多数据源接入 | ❌ | 是工程体力活，不是设计能力 |
| 多模态（图片/表格法规） | ❌ | 工作量大、偏离主线，法律文本以纯文本为主 |
| 更快的向量库（换 Qdrant） | ❌ | 是"调参"不是"设计"，且当前不是瓶颈 |
| **时效性处理** | ✅ | **通用 RAG 完全不管这件事**，而法律场景下引用失效法条是致命的 |
| **条款级引用校验** | ✅ | 让引用从"看起来像"变成"可验证"，有量化指标（Citation F1） |

## 决定

**核心差异化 = 时效性处理 + 条款级引用校验。这两件事贯穿 M2/M3/M4/M5。**

### 一、时效性处理

**问题**：法条会修订、会废止、会**部分废止**。通用 RAG 不知道"哪一版有效"。

**设计**：

1. **每个 chunk 带三个日期**：`promulgated_at`（公布）/ `effective_at`（施行）/ `expired_at`（失效）
2. **从提问里抽时间**："我 2019 年入职，2025 年被裁" → 时间窗口 [2019, 2025] → 只保留时间窗口内有效的版本
3. **粒度到"款"**（见 ADR-009）：能回答"第 32 条第 1 款已废止，但整条仍有效"

**必测用例**：
> 《最高法劳动争议司法解释（一）》第 32 条**第 1 款**自 2025-09-01 起被《解释（二）》废止，整条仍有效。

### 二、条款级引用校验（三层）

**问题**：LLM 会编造引用。gowork Day55 实测过——top_k 提高到 5 之后，模型把引用飘到了诱导段落，**"标了引用"不等于"引用是对的"，比不标更糟**。

**设计**（后端强制校验，不信任模型输出）：

```
模型输出引用 → 正则抽取 (法规名, 条, 款, 项)
            → 法规别名归一化（"劳动合同法" / "劳动法" 不是一个东西！）
            → 三层校验：
               ① 法规存在？
               ② 该条款存在？
               ③ 该版本在该时间点有效？
            → 不通过则拒绝 / 修正回答
```

**关键点**：法规别名归一化必须有张表。用户说"劳动法"可能指《劳动法》也可能指《劳动合同法》——**这是两部完全不同的法律**，搞混了答案就是错的。

### 三、为什么这两件事值钱

1. **通用平台做不到。** Dify / RAGFlow 是通用框架，不会内置"法条部分失效"这种领域知识。
2. **可量化。** 时效性 → 评估集的"时效适用型"题目（占 20%）正确率对比；引用校验 → **Citation F1** + 校验器拦截率。**论文实验章直接有内容。**
3. **有理论支撑。** 调研发现已有论文做过类似工作：明确条款号的查询走 SQL 精确匹配，`Citation F1` 达 **0.897**，而纯 BM25 只有 **0.718**。这给了定量预期的锚点，也让方案不是拍脑袋。

### 四、延伸：条款号精确查询（M3）

时效性和引用校验之外，附带一个**准确率提升最明显**的设计：

> 用户直接问"**第 19 条**写的什么" → **不走向量检索**，正则抽条款号 → SQL 精确查 `chunks.article_no`。

论文实证这是提升最明显的一招（`Recall@5` 0.963）。而且**实现简单、收益巨大**——面试时这是个很好的"我知道什么时候不该用向量检索"的例子。

## 代价

- **语料标注工作量**：要人工核对时效性字段（尤其"部分失效"）。→ 第一版只做 11 部法，可控
- **解析复杂度上升**：款级粒度 + "之一" + 款级失效，解析器比通用分块器复杂得多（M2 要 4 天）→ 这是**有意选择的难点**
- **评估集构造成本**：时效适用型题目（20%）需要设计时间场景，比事实型题目难造。→ LLM 生成候选 + 人工校验
- **可能做不完**：时效性依赖语料质量，如果语料时效字段不可靠，这条线会打折。→ 已识别为风险，M2 第 2 天就有验证点（`sxx` 编码实测）

## 面试怎么答

> "现在 RAG 知识库项目很多，你这个有什么不一样？"
>
> 我不做"能建库能问答"——那个今天没有区分度，Dify 一天就能搭出来。
>
> 我的差异化在**法律领域特有、通用平台做不到**的两件事。
>
> 第一是**时效性**。法条会废止，而且会**部分废止**。举个真实例子：最高法《劳动争议司法解释（一）》第 32 条，它的第 1 款在 2025 年 9 月 1 号被新的司法解释废掉了，但整条还是有效的。通用 RAG 只按文本相似度检索，它会给你一个失效的版本，而它自己不知道。我做了三层：chunk 带三个时间日期、从提问里抽时间做窗口过滤、粒度做到款级。
>
> 第二是**条款级引用校验**。大模型会编引用，我在上个项目里实测过——把召回数量提高之后，引用会飘到那些"看起来相关但不是答案"的段落上。标了引用但不校验，比不标更危险，因为用户会更相信它。所以我的后端不信任模型输出，抽出引用之后做三件事校验：法规存在吗、条款存在吗、这个版本在那个时间点有效吗，不通过就拒绝回答。指标用 Citation F1。
>
> 这两件事都有量化结果——评估集里时效适用型题目占 20%，能对比有/无时间过滤的正确率；引用准确性用 Citation F1 和校验器拦截率。

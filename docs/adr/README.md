# 架构决策记录（ADR）索引

> 面试前**通读一遍这个目录**，就是完整的项目叙事。
> 论文的"关键技术选型"章节可以直接从这里取材。

## 怎么用

- **每做一个关键决策写一条**，不要事后补——事后补的 ADR 会丢失"当时为什么纠结"这个最有价值的部分
- 格式固定：背景 / 备选 / 决定 / 代价 / **面试怎么答**
- **"面试怎么答"是重点**——把 ADR 翻译成口语化的回答，面试前直接背

## 模板

```markdown
# ADR-0XX：<决策标题>

> 状态：已采纳 · <日期>

## 背景
（什么问题逼着你要做这个决策？不写背景的 ADR 没有价值）

## 备选
| 方案 | 优点 | 缺点 |

## 决定
选哪个 + 为什么

## 代价
（**必须写**。没有代价的决策说明你没想清楚，面试官一问就露馅）

## 面试怎么答
> 面试官会怎么问？
>
> 口语化的完整回答。
```
